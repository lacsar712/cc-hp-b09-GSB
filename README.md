# 饮片炮制记录台

一条记录是一整包炮制文书，里面是工序数组，不是拆成多列指标的普通表单。清炒温度和时长不在范围内就不能放行。

```bash
docker compose up --build
```

## 处方投料汇总卡

炮制员为一张处方建立「汇总卡」，挂上多味饮片和各味目标克重。

- 顶栏的「处方汇总链」进入专页落地页（`#/rx`），首页（`#/`）保留现场记录台，首页那一张卡不算专页。
- 落地页含三块：**建卡区**、**现场汇总**、**已签发快照**。
- 每张卡有自己的专页（`#/rx/{cardId}`），按味汇总：目标克重、**已成功写入次数**、**结论集合**、**最近结论**。写入只能选本卡已挂的饮片，写卡外饮片返回 422。
- 炮制员可在卡专页**签发处方快照**：冻结当时各味的次数与结论集合（`#/rx/{cardId}/snapshots/{snapshotId}`）。签发之后新写只改现场卡，已签发快照不再变化。
- 质检员可打开现场卡与任何快照，但页面不提供建卡/写入/签发入口；直接调接口一律 403。

## 验收

原记录台：

1. processor 登录后，甘草为放行，黄芩为未放行（温度过低）。
2. 再写一条温度 200 的清炒，结论仍是未放行。
3. checker 看不到写入按钮。

处方汇总卡与快照：

1. processor 进入「处方汇总链」，建卡「四君子汤」，挂 甘草60g、党参90g、茯苓90g。
2. 在卡专页给甘草写一笔合格清炒 → 现场甘草次数为 **1**，最近结论「放行」。
3. 点「签发快照」→ 打开快照，甘草次数为 **1**。
4. 回到现场卡再给甘草写一笔（如温度 200）→ 现场次数变为 **2**，最近结论「未放行」，结论集合为 {放行, 未放行}。
5. 重新打开第 3 步那张快照 → 甘草次数仍为 **1**、结论仍为「放行」，现场卡的后续写入没有改动它。
6. 退出改用 checker 登录：能看现场卡与快照；看不到建卡区表单、写入与签发按钮（对应接口返回 403）。
